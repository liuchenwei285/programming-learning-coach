# 批改模板（grading-template）

> 对应 `scripts/grading.py` + `templates/practice.md`。结构对齐范例《10月18日练习》。

## 一、逐题九段（缺一不可，代码会列出 `missing_sections`）

| # | 段落 | 字段 | 来源 |
| :-- | :-- | :-- | :-- |
| 1 | 我的答案 | `my_answer` | 学习者提交，**逐字保留**（含缩进、空行、注释），代码块标语言 |
| 2 | 正确性 | `correctness` | 完全正确 / 部分正确（x/y）/ 错误 / 未提交（未完成） |
| 3 | 错误位置 | `error_location` | 文本题自动给出「第 N 行不一致」；代码题给行号 + 片段；无错写「无明显错误」 |
| 4 | 错误原因 | `error_reason` | 教练写：说清「为什么错」，不是复述「哪里错」 |
| 5 | 知识点 | `knowledge_points` | 全部写成 `[[知识点]]` |
| 6 | 修改建议 | `suggestion` | 最小改动方案，**保留学习者原有思路** |
| 7 | 标准答案 | `reference_solution` / `expected_answer` | 从 `.private/` 读出；文本题用 ```text，代码题用 ```c |
| 8 | 逐步讲解 | `step_by_step` | 出题时写好的 `explanation` 会被自动复用；教练可覆盖。数学式用 LaTeX |
| 9 | 更好写法 | `better_approach` | **仅限当前水平**：涉及未学知识点会被自动移除并说明 |

文本题（输出预测/追踪/分析/辨析）没有「改写代码」的空间，第 9 段会写成
「本题为文本作答，不涉及改写代码；更简洁的表述见标准答案的逐条讲解」。

## 二、两条判定路径

**A. 文本作答**（`answer_kind: text`）→ 逐行对照
- 规则：按行去空白后比较，**Tab 与多空格等价**（范例第 2 题里 `A\tB` 与 `A    B` 算一致）；
  大小写、标点、数字差异算错（范例里 `c:\Code\test` vs `C:\Code\test` 判为错误）。
- 产出：`text_diff` 对照表（行号 / 我的答案 / 标准答案 / 判定）+ `matched/total` + 出错行号。
- 得分 = 一致行数 / 标准答案行数 × 100。范例第 1 题 4 行错 1 行 = 75 分。
- 行级错误定位是自动的；**错误原因与修改建议必须教练写**，没写就留占位「（模型未提供，不编造）」。

**B. 代码作答**（`answer_kind: code`）→ 沙箱编译运行
- 能跑：产出用例表（输入 / 期望 / 实际 / 结果）+ 编译警告 + 隔离信息。
- 跑不了（无工具链、编译失败、超时）：必须写 **"本次未运行，仅静态审查（原因：…）"**，
  并附静态审查发现；此时如需给分，教练必须显式提供 `manual_correct`（true/false/"partial"），
  正确性会标注「（静态审查判定）」，与真实运行结果区分。

## 三、未提交的题目

- `status = 未完成`、`correctness = 未提交（未完成）`、`my_answer = null`、`score = null`。
- **不编造**：不写假想答案、不给分数；得分只按已提交题目计算（`score_submitted_only`），
  另给 `score_including_unsubmitted_as_zero` 作对照，并在文档里标明口径。
- 不产生掌握度事件（未提交不升不降）。

## 四、整体评价（6 个维度，全部必填）

1. **知识理解**：概念是否准确、有无混淆（引用具体题号）
2. **代码编写**：命名、结构、边界处理、编译警告数（文本题则看表述是否完整、是否逐条回应要求）
3. **逻辑思维**：解题路径是否清晰、有没有隐含假设错误（如「max 初值取 0 等于假设答案非负」）
4. **知识点掌握**：结合本次事件后的最新状态
5. **薄弱环节**：`mastery.weak_points()` + 本次错误归因
6. **训练建议**：下一步练什么、怎么练、练到什么程度算过关

模型没写的维度渲染为「（模型未提供，不编造）」，不用套话填充。

## 五、练习文档的「总结」部分（对齐范例）

| 小节 | 内容 | 来源 |
| :-- | :-- | :-- |
| 一、知识点速查表 | `知识点 | 要点 | 相关题号` 三列 | 题号自动统计；**要点由教练写**（`meta.kp_table`），缺则占位 |
| 二、目前最需要改进的 N 点 | 编号列表，每条引用具体题号 | `meta.improvements` |
| 三、做得好的地方 | 项目符号，引用具体题号 | `meta.good_points` |
| 四、未掌握知识点与掌握度变化 | 本次 `学习中 → 待检验` 之类的变化 + 依据题号；仍未达「基本掌握」的清单 | **自动生成**（来自掌握度档案） |
| 五、下一步建议 | 编号列表 | `meta.next_steps` |

「按主题查笔记」一行由 `meta.topic_links` 提供（把知识点映射到你 Vault 里已有的笔记，如
`数据类型 → [[数据类型]]、[[C-数据类型-内存占用图-说明|数据类型内存占用图]]`）。

## 六、`notes.json`（教练填写）格式

```json
{
  "Q1": {
    "error_location": "第 3 行：我写 1.2，标准答案是 3.5",
    "error_reason": "7 / 2.0 是浮点除法，应得 3.5；1.2 是把 7/2 当成 3 再除以 2.5 之类的误算，属于没有验算",
    "suggestion": "写完每一行输出，用算术再验算一遍：7 ÷ 2 = 3.5",
    "step_by_step": "1) 第 1 行：%d 输出 7…\n2) 第 2 行：char 提升为 int…",
    "better_approach": null,
    "correctness_note": "4 行中 3 行一致"
  },
  "Q7": { "manual_correct": "partial", "error_location": "…", "error_reason": "…", "suggestion": "…" },
  "overall": {
    "知识理解": "…", "代码编写": "…", "逻辑思维": "…",
    "知识点掌握": "…", "薄弱环节": "…", "训练建议": "…"
  }
}
```
`manual_correct` 只在代码题无法运行时使用。文本题不需要它（逐行对照已自动判定）。

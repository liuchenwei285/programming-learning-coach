# 笔记解析规则（note-parsing）

> 对应 `scripts/parse_notes.py`。原则：能解析就解析，不能解析就**明确降级并说明**，绝不猜内容。

## 一、格式支持矩阵

| 格式 | 方式 | 依赖 | 缺失时 |
| :-- | :-- | :-- | :-- |
| `.md` `.markdown` `.txt` | 标准库读取 + 结构抽取 | 无 | — |
| `.docx` | 标准库 `zipfile` + `xml.etree`（读 `word/document.xml`，识别标题样式） | 无 | — |
| `.pdf` | `pypdf` → `PyPDF2` → `pdfminer` 依次尝试 | 可选 | `status=degraded`，提示"导出为 md/txt 或把关键页截图发我" |
| 图片 `.png/.jpg/.jpeg/.webp/.gif/.bmp/.tiff` | **由模型直接阅读**并转写要点 | 无（不做 OCR） | 报告里标 `needs_model_vision`，列出路径 |
| `.svg` | 视为图片（模型阅读） | 无 | 同上 |
| `.doc/.pptx/.xlsx/.rtf` | 不支持 | — | `degraded` + 请另存为 md/txt/docx/pdf |
| 其它未知扩展名 | 按纯文本尝试 | 无 | 失败则 `degraded` |

编码尝试顺序：`utf-8-sig → utf-8 → gb18030 → big5 → cp1252 → latin-1(兜底)`，实际使用的编码写进 `note`。

## 二、抽取内容

- `code_blocks`：``` 或 ~~~ 围栏，带语言（无标注时用 `guess_lang` 从内容推断）、起始行号、未闭合告警。
- `headings`：Markdown `#{1,6}` + docx 的 Heading 样式。
- `pitfalls`：含"易错/常见错误/陷阱/注意/坑/mistake/warning"等标记的行。
- `knowledge`：与 `knowledge-glossary.json` 匹配的结果，**每条都带依据**（文件、行号、片段）。
- `languages`：由代码块语言 + 特征（`#include`、`printf`、`def`、`print(`）加权统计。

## 二点五、证据分级 T1~T5（决定「要不要问」）

| 等级 | 判据 | 处理 |
| :-- | :-- | :-- |
| **T1 系统讲解** | 强别名命中 **1~4 级** Markdown 小标题 | 直接可用，**不询问** |
| **T2 代码示例** | 强别名命中**真实代码行**（代码块内的注释行不算） | 直接可用，**不询问** |
| **T3 正文明确提及** | 强别名在正文（非代码）命中 **≥3 次** | 直接可用，**不询问** |
| **T4 弱证据** | 只有泛别名命中；或命中全在预告句 / 目录式列举 / 排版规范笔记；或正文提及 <3 次 | **合并成一张表一次性问** |
| **T5 无命中** | 词库核心知识点但笔记完全没出现 | 未学习，**禁止作为解题必要条件** |

- 强别名 = `names`，泛别名 = `weak_names`（`return/变量/循环/地址/分号/栈/堆`…），泛别名命中**永远不能**单独支撑 T1~T3。
- 5~6 级标题只是大章节下的子条目（`###### 3.函数调用语句` 属于「语句分类」），**不算**系统讲解。
- 语言检测不到（纯文字笔记）时按 `--language` 兜底（默认 c）。

## 二点六、范围确认只做一次

- T1~T3 默认视为「学习中」，**直接出题，不逐项询问**。
- T4 才能问，且**合并成一张表一次性问完**，结果写入学习档案 `confirmed_scope`。
- 笔记指纹（内容 sha256 + 词库指纹）未变 → **直接沿用档案**；有新笔记只问**新增**歧义项。
- 「笔记出现过 ≠ 已掌握」不变：T1~T3 只给「学习中/待检验」，只能由练习升级。

## 三、匹配防误报的三条规则（重要）

1. **语言过滤**：先检测语言，再决定哪些词条参与匹配。C 语言笔记不会命中 Python 词条。
2. **符号不单独成立**：`& * % ++ << && ||` 这类符号别名必须与同词条的"词名"在同一文件共现，
   否则 `int *p` 里的 `*` 会把「指针」误判成已学。
3. **置信度标注**：只靠"变量/运算符/循环"等通用词命中 → `confidence: weak`，
   只能标「学习中」，且必须在知识点范围确认表里列出，由学习者确认或否决。

## 四、输出与后续

`parse_notes.py --json notes-report.json` 的输出直接喂给 `analyze.py`：

```
python parse_notes.py --input <笔记路径> --json work/notes-report.json
python analyze.py --report work/notes-report.json --records work/records.json \
                  --out work/analysis.json --print
```

`analyze.py` 产出七部分，每一项都注明依据来源（笔记 文件:行号 或 练习 会话+题号）：

1. **已学**（笔记接触过）2. **已掌握**（只能由练习确认）3. **未完全掌握**（练过但未达标）
4. **正在学**（笔记有、无练习记录，初始估计）5. **未学**（词库核心知识点但笔记没出现）
6. **代码示例与典型错误**（`scan_typical_errors`：if 里用 `=`、`scanf` 少 `&`、`void main`、`gets`、
   用了 `printf` 却没 `#include <stdio.h>` 等 + 笔记里标注的注意点）
7. **涉及语言**

图片笔记（`needs_model_vision`）由模型阅读后，把要点补写进确认表，并注明"依据：图片 <路径>"。

# 代码精读规则（code-reading-rules）

> 两种模式，**默认 A**。选择依据是学习者的掌握度，不是偏好。

## 模式 A：自编程序（默认，对应范例《C语言精读10篇》）

`scripts/reading.py` + `templates/code_reading.md`

**什么时候用**：指针 / 结构体 / 动态内存 / 多文件 等前置知识点还是「未学习」时**必须**用这个模式。
大型开源项目此时读不下去（大量指针、结构体、宏、多文件组织），硬推只会挫败。

**10 篇的硬要求**

1. 篇数 = 10；难度递增；**预习篇放最后**（`preview: true`，且必须写 `preview_uses` 说明用了哪些还没学的内容）。
2. **只能用已学知识点**：非预习篇的 `knowledge_points` 里出现「未学习」→ 报错。
3. 前几篇必须**对着本次薄弱点**（`mastery.weak_points()`）；未覆盖给警告。
4. 每篇必须能**一次读完**：一个完整、可编译、短小的程序（一般 ≤ 40 行），带中文注释逐行解释。
5. 每篇必填：`title` `why`（必须引用学习者的具体错误，如"你在第 1、4、10 题反复遇到整数除法"）
   `code` `knowledge_points` `related_notes` `predict_questions`(≥2) `watch_points`(≥2)
   `related_exercises`（对应练习的题号）`input_spec` `stdin`。
6. **实际输出必须来自真实运行**：`reading.py` 会用 gcc 编译并运行每篇程序，把 stdout 写进
   `actual_output`，并生成 `verify_line`（编译器、版本、有无警告、耗时）。
   - 编译失败或运行超时 → `compile_ok: false`、`actual_output: null`、
     `verify_line` 写「**未通过验证**：原因…实际输出留空 —— 不编造运行结果」。
   - 没有 gcc → 同上，写「未验证：本次未运行编译」。
   - 只有全部通过时，文档才可以写"所有程序都已编译运行验证，没有警告"。
7. **不得含开源字段**：`url` `repo` `path` `license` `author` 出现在 A 模式的条目里 → 报错
   （避免把没核验过的链接混进自编模式）。

**每篇的文档结构（模板已固定）**

```
## 第 N 篇｜<主题>
**为什么读：** <引用你的具体错误>
```c 完整程序（带中文注释）```
**输入：** <无输入 / 输入秒数，如 3725>
**先预测（别急着运行）：** 1. … 2. … 3. …
**实际输出：** ```text 真实运行结果```
**验证状态：** 已用 gcc 编译并运行（…）：无警告，上面的「实际输出」是真实运行结果
**读代码时盯住这几点：** - … - …
**相关笔记：** [[C语言]]（算术操作符）、[[11月1日练习]]（第 1 题）
```

**读法（写进文档开头，固定）**
① 先不要运行，在纸上写出你预测的输出；② 再编译运行，对照「实际输出」；
③ 不一致的地方，就是你要重点补的知识。

**文档结尾必须有「暂时先不要读的」**：由 `render_md.not_yet_md()` 依据「未学习」的知识点自动生成，
说明为什么现在不读大型开源项目，并给出 1→2→3 的过渡路径。

## 模式 B：真实开源片段（进阶）

`scripts/verify_sources.py` + `templates/code_reading_opensource.md`

**什么时候用**：`指针基础`、`结构体`、`内存区域与动态分配` 等都达到「学习中」及以上之后。

1. 10 份、难度递增、优先补薄弱点、**选片段不选整项目**（已验证条目必须给具体文件 `path`）。
2. 每份必填：`name` `language` `source` `url` `license` `difficulty` `reason`
   `knowledge_points` `focus` `method` `ideas` `tasks`(≥2)。
3. **联网核验**（纯标准库 urllib）：`GET /repos/{owner}/{name}` 确认仓库存在并取 `license.spdx_id`；
   `GET /repos/{owner}/{name}/contents/{path}?ref={branch}` 确认文件存在（目录不算）。
   结果标 **已验证 / 未验证**；限流（403/429）单独识别为「限流，本次无法核验」，不冒充「路径不存在」。
4. **离线降级**：`sanitize_offline()` 删掉 `url` `repo` `path` `license` `author`，只留项目名与学习价值描述，
   标 **待验证**。宁缺勿造：不给链接、不编造路径与作者。
5. **不复制第三方整份代码**：只给仓库 + 文件路径 + 函数名 + 行为描述；单次引用 ≤ 15 行并遵守许可证。
6. 许可证以 API 返回为准；返回 `NOASSERTION` 就照写，并提示"以仓库 LICENSE 文件为准"，不猜 SPDX 名。
7. 可选 `GITHUB_TOKEN` 环境变量把配额从 60 次/小时提到 5000 次/小时；仓库查询有缓存，同仓库多片段只查一次。

## 通用规则

- 精读文档文件名 `X月X日代码精读.md`，年份写进 frontmatter 的 `date`（见 `vault-rules.md`）。
- 所有知识点写 `[[双向链接]]`；每篇都要回链到对应的练习题号。
- 精读之后要落到练习：下次出题优先安排与精读篇目对应的知识点。

# 掌握度规则（mastery-rules）

> 本文是 `scripts/mastery.py` 的规格说明。代码与本文必须一致；冲突以本文为准并修代码。

## 一、核心原则：出现 ≠ 掌握

- 笔记里出现过某个知识点，**只能**说明"接触过"，不能推出"已掌握"。
- 掌握度**只由练习表现**决定（答对/答错的题目、次数、跨练习、是否组合题）。
- 仅凭笔记，状态上限是 **待检验**；`from_note_knowledge()` 若被要求写高于"待检验"的状态会直接抛 `MasteryError`。
- 冷启动（无历史记录）时，所有状态都带 `estimated: true`，必须向学习者说明"这是初始估计"。

## 二、五级状态

| 索引 | 状态 | 含义 | 能否用于出题 |
| :-- | :-- | :-- | :-- |
| 0 | 未学习 | 笔记与练习都没有依据 | ❌ 严禁（连"涉及"都不行） |
| 1 | 学习中 | 笔记提到，尚未经练习检验 | ✅ |
| 2 | 待检验 | 笔记系统讲过，或答对过 1 次 | ✅ |
| 3 | 基本掌握 | ≥2 道不同题目答对 | ✅ |
| 4 | 熟练掌握 | ≥3 道不同题、跨 ≥2 次练习、含 1 次组合题答对 | ✅ |

## 三、升级 / 降级规则（逐条对应代码）

1. **一次答对最多升到「待检验」**
   当前状态 < 待检验 时，单次 `correct` 事件的封顶是 待检验（`cap = IDX["待检验"]`）。
2. **至少 2 次不同题目答对 → 基本掌握**
   `len(set(correct_questions)) >= 2`。同一题重复答对不算两次。
3. **至少 3 次、跨 2 次练习、含一次组合题答对 → 熟练掌握**
   `len(correct_questions) >= 3 and len(sessions) >= 2 and combined_correct`。
   组合题 = `is_combined: true` 的题目（一题同时考 ≥2 个知识点）。
4. **出现错误则降一级**
   任何一次 `correct: false` → 降一级。
   部分正确（用例只过了一部分）按"出现错误"处理，事件里同时记 `partial: true` 供讲解使用。
   **降级下限（两条）**：
   - 有笔记依据的知识点最低降到「学习中」，不会掉回「未学习」（否则它永久无法出题）；
     完全没有笔记依据的知识点可以降回「未学习」。开关：`mastery.DEMOTE_FLOOR_WITH_NOTES`。
   - **答错只下调该题 `required_knowledge_points`（解题必需）里的知识点**；
     一道题往往涉及 5~6 个知识点，错因通常只落在必需的那 1~3 个上，
     把全部涉及项都降级会让薄弱点清单失去指导意义。答对时则给所有涉及知识点记功。
5. 降级后重新答对，按第 1 条重新爬升（不会因为历史记录一次性跳回原级）。
6. 未提交 → **不产生任何事件**，不升不降，不编造表现。

## 四、冷启动策略

- 只标 **学习中 / 待检验**：
  - 笔记里有小标题系统讲解，或有对应代码示例 → 待检验；
  - 仅提及（含只用通用词命中的弱匹配）→ 学习中。
- 首次练习**难度偏保守**：难度 5 的题最多 1 道，且不出现需要 3 个以上知识点组合的题；
  以 2-3 个知识点的组合题为主，先建立可靠的能力基线。
- 必须明确告知学习者："这是初始估计，掌握度以练习结果为准。"

## 五、薄弱点定义（出题优先覆盖）

满足任一条件即为薄弱点，`mastery.weak_points()` 输出：

- 有答错记录（`wrong_questions` 非空）；
- 练过但一次都没答对（`practice_evidence` 非空且 `correct_questions` 为空）。

注意：冷启动时几乎所有知识点都是「待检验」，所以**不能**把"状态 ≤ 待检验"当作薄弱点，
否则整张表都会被标红。

薄弱点必须在下次出题中优先安排，但**不得重复原题**（`questions.py` 用描述指纹查重，重复会报错）。
